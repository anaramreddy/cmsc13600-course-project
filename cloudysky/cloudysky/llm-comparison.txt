My data model adds several design layers that the robot-generated one omits. I used Django’s GenericForeignKey for both Media and ModerationAction so a single table can attach to either posts or comments and easily extend to other entities in the future. I also included denormalized moderation fields (is_suppressed, reason, message, timestamps) directly on both Post and Comment for faster filtering and simpler API queries. In addition, my version tracks byte counts for analytics and provides helper methods for visibility rules, ensuring that authors and administrators can still view suppressed content while other users see placeholders.

The robot model is simpler and easier to read—it uses explicit nullable foreign keys (post, comment) instead of GenericForeignKey and omits analytics fields. While that design works fine for this assignment, it would require schema changes if new attachable content types were added later. Overall, I prefer my model for its extensibility and efficiency, but I appreciate the robot model’s clarity and straightforward structure.
